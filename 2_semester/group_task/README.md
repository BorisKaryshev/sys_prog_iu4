# Общая инфа

Есть самолет, управляющая система на нем - Linux

Нам нужно написать написать модуль ядра, которым мы сможем влиять на датчик (другой модуль)
Наш модуль ядра должен быть скрытным.

Наш процесс (порожденный нашим модулем ядра) не должен быть виден утилитами:
- `ps aux`
- `df -h`
- `netstat`
- `tulplan`
- `top`
- `trace` (`strace` etc)


# Конкретно наше условие
Нужно сделать модуль ядра
Его нужно скрыть: он не должен светиться в `lsmod` или `cat /proc/modules`
Модуль должен создавать процесс, который будет невиден через `ps auxfww`

# Описание решения
[Точка входа](./hidden_miner.c)

Модуль ядра разбит на два логических блока:
- timer
- hidepid

### timer
Создает процесс с `while(1) timer_cnt += 1;`. Маунтит вывод таймера в /sys/hidden_timer/timer и pid созданного процесса в /sys/hidden_timer/pid.

Вывести результат таймера: `cat /sys/hidden_timer/timer`
Установить новое значение для таймера: `echo 123 > /sys/hidden_timer/timer`

Вывести pid процесса: `cat /sys/hidden_timer/pid`

### hidepid

ps и прочие утилиты получают список процессов из /proc
соответственно чтобы скрыть процесс из системы нужно спрятать папку из /proc

Есть syscall называется getdentes64.

Его описание:

    getdents64 — это системный вызов Linux, который читает содержимое папки (директории)
    и возвращает список файлов и подпапок внутри неё в виде структур с именами, inode и типами.

    Он используется такими программами, как ls, find или оболочкой, чтобы узнать, какие файлы лежат в папке.
    В отличие от простого чтения имён, он выдаёт сразу «сырые» данные, которые ядро хранит о записях в каталоге.


    Его сигнатура:
    ssize_t getdents64(int fd, void *dirp, size_t count);

    fd - папка для которой смотрим содержимое
    dirp - буффер, в который будет сохранен результат - массив элементов
    count - размер буффера

    возвращает количество прочитанных байтов

Соответственно если добавить фильтр после выполнения этого syscall, то можно спрятать любой путь от пользователя

Есть такая технология как kretprobe:

    TLDR: можно встроить callback, перед вызовом syscall и после него

    kretprobe — это механизм трассировки ядра Linux, который срабатывает в момент выхода из
    заданной ядерной функции (например, когда она завершает работу) и позволяет перехватить её возвращаемое значение.

    Он используется для отслеживания ошибок, подсчёта вызовов или измерения времени выполнения функций прямо в ядре, без перекомпиляции.
    В отличие от обычного kprobe (срабатывает на входе в функцию), kretprobe даёт доступ к результату работы функции и к её аргументам (через специальные сохранённые данные).

Соответственно в модуле hidepid как раз реализован подход выше

kretprobe доволно низкоуровневая вещь - аргументы syscall напрямую не видны в callback. В нем видны регистры, которые были на опр момент (на входе syscall или на выходе).

Код писался и тестировался под x86_64, на котором код компилируется под SystemV ABI (конвенция об использовании регистров при вызове функций).

Согласно этому ABI - аргументы функции передаются через регистры в определенном порядке.
И после "входа" в функцию, их значения из этих переменных "забираются".

Так что на выходе из функций значение входных аргументов функции извлечь нельзя.
Решение - pre-callback, в котором кладем данные в спец буффер, предоставляемый kretprobe.
В post-callback копируем результат из внешнего буффера во внутренний и фильтруем, после чего выдаем фильтрованный результат в user-buffer.
